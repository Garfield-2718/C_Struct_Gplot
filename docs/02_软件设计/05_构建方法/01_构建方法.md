# C_Struct_Gplot 构建方法

本项目是基于 **Electron + Vue 3 + TypeScript** 的桌面应用，使用 **electron-vite** 进行三目标（main / preload / renderer）构建，使用 **electron-builder** 进行跨平台打包分发；同时集成了一个外部 **CLI sidecar 二进制**（`struct_topology`，由独立仓库 `C_Struct_Gplot_CLI` 经 PyInstaller 打包），随应用一同分发。本文系统梳理从环境准备到完整发布的全部构建方法。

---

## 1. 概述

| 层面        | 技术/工具                                    | 说明                                  |
| ----------- | -------------------------------------------- | ------------------------------------- |
| 运行时框架  | Electron `^39.2.6`                           | 主进程 / 预加载 / 渲染进程三进程模型  |
| 前端框架    | Vue `^3.5.25` + vue-router `^4.6.4`          | 渲染进程 UI                           |
| 语言        | TypeScript `^5.9.3`                          | 全栈类型约束                          |
| 构建工具    | electron-vite `^5.0.0`（底层 vite `^7.2.6`） | 编译打包 main/preload/renderer        |
| 打包分发    | electron-builder `^26.0.12`                  | 生成 Windows/macOS/Linux 安装包       |
| CLI sidecar | PyInstaller（Python 3）                      | 将 `struct_topology` 打成单文件二进制 |

- 入口：`package.json` 的 `main` 指向 `./out/main/index.js`（electron-vite 构建产物）。
- 构建目标由 `electron.vite.config.ts` 定义，包含 `main`、`preload`、`renderer` 三部分。
- CLI 二进制的集成背景、平台约束与运行时定位逻辑详见 [`../04_CLI集成/CLI集成.md`](../04_CLI集成/CLI集成.md)。

## 2. 前置依赖

### 2.1 通用依赖（构建 Electron 应用必需）

- **Node.js**：实测 `v22` 可用（`@types/node` 为 `^22.19.1`）。
- **npm**：随 Node.js 附带，用于安装依赖与运行 scripts。
- **国内镜像（可选）**：若 Electron 二进制下载缓慢或失败，先配置镜像再安装：

```bash
npm config set electron_mirror https://npmmirror.com/mirrors/electron/
```

- **Linux/WSL 运行 Electron 所需系统库**（打包 AppImage/deb 及运行时需要）：

```bash
sudo apt install -y build-essential libgtk-3-dev libnotify-dev \
  libnss3 libxss1 libasound2t64 libxtst6
```

### 2.2 CLI sidecar 构建额外依赖

仅在需要构建 CLI 二进制（`build:cli` / `dist:*`）时才需要：

- **python3**、**pip**、**PyInstaller**。
- Linux/WSL 当前环境安装方式：

```bash
# 1) 安装 pip 与 venv
sudo apt-get install -y python3-pip python3-venv

# 2) 以用户级安装 PyInstaller
python3 -m pip install --user pyinstaller

# 3) 验证
python3 -m PyInstaller --version
```

> **PEP 668 提示**：若第 2 步报 `externally-managed-environment` 错误（新版 Debian/Ubuntu 常见），追加 `--break-system-packages`：
> `python3 -m pip install --user pyinstaller --break-system-packages`

`scripts/build-cli.mjs` 在构建前会**主动探测 PyInstaller**（执行 `python3 -c "import PyInstaller"`）：探测通过才继续；缺失时只打印上述安装指引并以退出码 `1` 退出，**绝不自动执行 `sudo` 或安装依赖**。

### 3.3 开发模式（WSL2 注意事项）

`npm run dev` 在 WSL2 下已针对性优化：

- **禁用硬件加速**：`src/main/index.ts` 中，当 `process.platform === 'linux'` 时调用 `app.disableHardwareAcceleration()`，改用软件渲染规避 WSL2 的 GPU 问题（Windows/macOS 保持默认 GPU 加速）。
- **polling HMR**：`electron.vite.config.ts` 的 `renderer.server.watch` 设置 `usePolling: true`、`interval: 300`，解决 WSL2 下文件系统事件不触发导致热更新失效的问题。

## 4. Electron 应用打包分发

### 4.1 构建产物与打包产物

- `npm run build` 由 electron-vite 生成三目标产物到 `out/`：`out/main/index.js`、`out/preload/index.js`、`out/renderer/`。
- `electron-builder` 读取 `out/` 产物打包，最终安装包输出到 `dist/`。

### 4.2 打包命令

```bash
# 免安装目录（快速验证打包是否正确，产物在 dist/ 下的 *-linux-unpacked / win-unpacked 等）
npm run build:unpack

# 各平台安装包（不含 CLI sidecar）
npm run build:win
npm run build:mac
npm run build:linux
```

### 4.3 `electron-builder.yml` 关键配置

| 配置项                 | 值                                       | 说明                                                                       |
| ---------------------- | ---------------------------------------- | -------------------------------------------------------------------------- |
| `appId`                | `com.electron.app`                       | 应用唯一标识                                                               |
| `files`                | 含 `!binaries/**`、`!scripts/**`         | **排除** CLI 二进制与构建脚本，避免被打进 asar（与 `extraResources` 重复） |
| `asarUnpack`           | `resources/**`                           | 将 `resources/` 解包出 asar（注意与 CLI 的 `binaries/` 区分，见第 7 节）   |
| `win.extraResources`   | `from: binaries/windows-x64` → `to: cli` | 把 Windows CLI 二进制分发到 `resources/cli`                                |
| `linux.extraResources` | `from: binaries/linux-x64` → `to: cli`   | 把 Linux CLI 二进制分发到 `resources/cli`                                  |
| `linux.target`         | `AppImage` / `snap` / `deb`              | Linux 打包格式                                                             |
| `npmRebuild`           | `false`                                  | 不在打包阶段重建原生依赖                                                   |

`extraResources` 的 `filter` 均为 `['**/*', '!.gitkeep']`，即分发目录内除占位文件 `.gitkeep` 外的全部内容。

### 4.4 打包后 CLI 的运行位置

打包后 CLI 二进制位于：

```
<安装目录>/resources/cli/struct_topology        # Linux / macOS
<安装目录>/resources/cli/struct_topology.exe    # Windows
```

运行时由主进程 `src/main/cli-service.ts` 的 `resolveCliBinary()` 定位：

- 打包态（`app.isPackaged`）：`path.join(process.resourcesPath, 'cli', exeName)`
- 开发态：`path.join(app.getAppPath(), 'binaries', platformDir, exeName)`

## 5. CLI sidecar 二进制构建

### 5.1 `build:cli` 完整流程

`npm run build:cli` 执行 `node scripts/build-cli.mjs`，共 5 个步骤：

1. **解析/获取源码**（`resolveCliSource`）：
    - 默认从 GitHub 仓库 `https://github.com/Garfield-2718/C_Struct_Gplot_CLI.git` `git clone` 到项目根的缓存目录 `.cli-src/`（已加入 `.gitignore`）。
    - 缓存已存在时：`git fetch origin` → `git remote set-head origin -a` 校准默认分支 → 比对本地 `HEAD` 与远端默认分支 tip；落后则 `git pull --ff-only` 更新，一致则复用。
    - **开发调试**：将脚本顶部常量 `USE_LOCAL_CLI` 改为 `true`，即改用本地路径 `LOCAL_CLI_DIR`（当前为 `/home/wsl/code/C_Struct_Gplot_CLI`），跳过 clone。
2. **探测 PyInstaller**（`probePyInstaller`）：缺失即报错退出（见第 2.2 节）。
3. **调用打包脚本**（`buildCli`）：在 CLI 源码目录下执行 `python3 build_package/build_package.py`（Windows 用 `python`）。**默认即单文件模式，脚本不接受 `--onefile` 参数**（传入未知参数会导致 argparse 以退出码 2 报错）。
4. **定位产物**（`locateArtifact`）：产物路径为 `<cli>/build_package/dist/<platformDir>/<exeName>`。
5. **复制产物**（`copyArtifact`）：复制到本项目 `binaries/<platformDir>/<exeName>`；非 Windows 平台执行 `chmod 0o755` 保留可执行位。

### 5.2 平台映射表

平台映射是 `build-cli.mjs` 与 `cli-service.ts` 共享的契约，两侧必须严格一致：

| `process.platform` | `systemTag` | `platformDir`（x64）                          | `exeName`             | `pythonCmd` |
| ------------------ | ----------- | --------------------------------------------- | --------------------- | ----------- |
| `win32`            | `windows`   | `windows-x64`                                 | `struct_topology.exe` | `python`    |
| `linux`            | `linux`     | `linux-x64`                                   | `struct_topology`     | `python3`   |
| `darwin`           | `macos`     | `macos-<arch>`（`macos-x64` / `macos-arm64`） | `struct_topology`     | `python3`   |

> `archTag` 由 `process.arch` 推导：`arm64` → `arm64`，其余 → `x64`。

### 5.3 `dist:win` / `dist:linux`：完整分发

`dist:*` 串联三步：`build-cli.mjs --target <平台>` + `npm run build` + `electron-builder --<平台>`。

```bash
# 在 Windows 本机执行：构建 CLI + 应用 + Windows 安装包
npm run dist:win

# 在 Linux 本机执行：构建 CLI + 应用 + Linux 安装包
npm run dist:linux
```

> **`--target` 守卫（重要）**：`build-cli.mjs` 的 `validateTarget()` 会解析 `--target <win|linux|mac>`，与宿主平台推导出的 `systemTag` 比对；**不一致时立即报错退出**（退出码 1）。这是为了避免「在 Linux 上跑 `dist:win` 却静默只产出 `linux-x64` 二进制、导致 `electron-builder --win` 从空的 `binaries/windows-x64` 打出缺少 `struct_topology.exe` 的安装包」。
>
> 由于 **PyInstaller 不能交叉编译**，`dist:*` 必须在**目标平台本机**执行——Windows 二进制只能在 Windows 上产出。

### 5.4 二进制不入库

- `.gitignore` 排除 `binaries/*/struct_topology*`（保留 `.gitkeep` 占位）与 `.cli-src/`。
- CLI 二进制由 `build:cli`（或 `dist:*`）在打包前**按需生成**，不提交到仓库。

## 7. 注意事项 / 常见问题

### 7.1 PyInstaller / pip 缺失

`build:cli` 报「缺少 PyInstaller」或「未找到 Python」时，按第 2.2 节安装 `python3-pip`、`python3-venv` 与 PyInstaller（PEP 668 环境加 `--break-system-packages`）。脚本不会自动安装。

### 7.2 WSL2 下 Electron 无法启动 / 白屏

Linux/WSL2 已在 `src/main/index.ts` 中对 `process.platform === 'linux'` 调用 `app.disableHardwareAcceleration()` 禁用硬件加速；HMR 不生效则由 `electron.vite.config.ts` 的 `usePolling: true` 保障。若仍异常，检查是否安装了第 2.1 节列出的系统库。

### 7.3 Windows 二进制必须在 Windows 本机产出

PyInstaller 不能交叉编译。在 Linux 上执行 `dist:win` 会被 `--target` 守卫直接拦截报错；请在 Windows 本机执行 `npm run dist:win`。

### 7.4 `binaries/` 与 `resources/` 的区别（勿混淆）

| 目录                      | 用途                    | 打包处理方式                                                             | 运行时位置                                        |
| ------------------------- | ----------------------- | ------------------------------------------------------------------------ | ------------------------------------------------- |
| `binaries/<platformDir>/` | 存放 CLI sidecar 二进制 | `files` 用 `!binaries/**` **排除**出 asar；`extraResources` 分发到 `cli` | `process.resourcesPath/cli/struct_topology[.exe]` |
| `resources/`              | 应用自身静态资源        | `asarUnpack: resources/**` 解包出 asar                                   | 随应用解包目录                                    |

> CLI 二进制走 `extraResources` → `process.resourcesPath/cli`，**不进 asar**（可执行文件无法从 asar 内运行）；请勿与 `asarUnpack` 处理的 `resources/` 混淆。

### 7.5 构建缓存与清理

执行 `npm run clean` 可一次性清除所有构建产物与缓存（跨平台，基于 Node.js `fs.rmSync`）：

| 清理目标             | 说明                                                  |
| -------------------- | ----------------------------------------------------- |
| `out/`               | electron-vite 三目标构建产物                          |
| `dist/`              | electron-builder 打包产物（AppImage/deb/snap/目录等） |
| `node_modules/.vite` | Vite 预构建缓存                                       |
| `.eslintcache`       | ESLint `--cache` 生成的缓存文件                       |

> 该命令不删除 `node_modules/` 本身；若需完全重置依赖，请额外执行 `rm -rf node_modules && npm install`。
