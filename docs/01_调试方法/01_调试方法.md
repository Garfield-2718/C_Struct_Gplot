# C_Struct_Gplot 调试方法

本项目基于 **Electron + Vue 3 + TypeScript + electron-vite** 构建，包含主进程（Main）、预加载脚本（Preload）和渲染进程（Renderer）三个部分。以下分别介绍各环节的调试方法。

---

## 1. 开发环境启动

```bash
# 安装依赖（若 Electron 二进制下载失败，先配置国内镜像）
npm config set electron_mirror https://npmmirror.com/mirrors/electron/
npm install

# 启动开发服务器（自带 HMR 热更新）
npm run dev
```

启动后，electron-vite 会同时启动：

- **主进程**：Node.js 环境，运行 `src/main/index.ts`
- **渲染进程**：Vite 开发服务器，提供 HMR，运行 `src/renderer/` 下的 Vue 应用
- **预加载脚本**：`src/preload/index.ts`，在渲染进程页面加载前执行

---

## 2. VSCode 断点调试（推荐）

项目已在 `.vscode/launch.json` 中预配置了三个调试配置：

### 2.1 调试主进程（Debug Main Process）

- 在 VSCode 中按 `F5`，选择 **Debug Main Process**
- 在 `src/main/index.ts` 中设置断点即可命中
- 原理：通过 `electron-vite --sourcemap` 启动，VSCode 以 Node 调试器附加到主进程

### 2.2 调试渲染进程（Debug Renderer Process）

- 选择 **Debug Renderer Process** 配置
- 使用 Chrome 调试协议（端口 `9222`）附加到 Electron 的渲染进程
- 在 `src/renderer/src/` 下的 `.vue` 或 `.ts` 文件中设置断点
- 需要先启动主进程调试（主进程会开启 `REMOTE_DEBUGGING_PORT=9222`）

### 2.3 同时调试主进程 + 渲染进程（Debug All）

- 选择 **Debug All** 复合配置，一键同时附加两个调试器
- 可同时命中主进程和渲染进程的断点

### 2.4 调试预加载脚本

预加载脚本运行在独立沙箱中，调试方式：

1. 在 `src/preload/index.ts` 中加入 `debugger` 语句：
    ```ts
    debugger // 在此处暂停
    import { contextBridge } from 'electron'
    ```
2. 使用 **Debug All** 启动，主进程断点命中后逐步执行到预加载脚本
3. 或者在 DevTools 的 Console 中通过日志排查（见第 3 节）

## 3. Chrome DevTools 调试（渲染进程）

### 3.1 打开 DevTools

- **开发模式下按 `F12`** 即可打开 DevTools（由 `optimizer.watchWindowShortcuts` 实现）
- 也可在代码中手动打开：
    ```ts
    mainWindow.webContents.openDevTools()
    ```

### 3.2 常用调试功能

| 功能            | 说明                                       |
| --------------- | ------------------------------------------ |
| **Elements**    | 检查 Vue 渲染的 DOM 结构                   |
| **Console**     | 查看渲染进程日志、执行临时 JS              |
| **Sources**     | 设置断点、单步调试 Vue 组件代码            |
| **Network**     | 查看网络请求、资源加载                     |
| **Application** | 检查 localStorage、sessionStorage、Cookies |
| **Performance** | 分析渲染性能                               |

### 3.3 Vue DevTools

如需调试 Vue 组件状态（响应式数据、Pinia store 等），可安装 Vue DevTools 扩展：

```bash
# 方式一：通过 Electron 扩展加载（开发模式下）
# 先安装 Vue DevTools Chrome 扩展，然后在 main/index.ts 中添加：
app.whenReady().then(async () => {
  await session.defaultSession.loadExtension('/path/to/vue-devtools-extension')
})
```

> 注意：生产环境中 DevTools 扩展不会生效。

## 4. 主进程日志调试

### 4.1 console.log

主进程中的 `console.log` 会输出到 **启动终端**（不是 DevTools Console）：

```ts
// src/main/index.ts
ipcMain.on('ping', () => console.log('pong')) // 终端中可见
```

### 4.2 日志文件

Electron 可将日志写入文件，适合排查启动阶段的崩溃问题：

```ts
import { app } from 'electron'
import * as fs from 'fs'

const logStream = fs.createWriteStream(app.getPath('logs') + '/main.log', { flags: 'a' })
console.log = (...args) => logStream.write(args.join(' ') + '\n')
```

日志路径通常为：

- Linux: `~/.config/<appName>/logs/`
- 可通过 `app.getPath('logs')` 获取实际路径

## 5. IPC 通信调试

项目中主进程与渲染进程通过 IPC 通信（见 `App.vue` 中的 `ipcHandle`）：

### 5.1 日志追踪

在主进程和渲染进程两端同时打印日志：

```ts
// 主进程 src/main/index.ts
ipcMain.on('ping', () => {
    console.log('[IPC] 收到 ping 消息')
})

// 渲染进程 src/renderer/src/App.vue
const ipcHandle = (): void => {
    console.log('[IPC] 发送 ping')
    window.electron.ipcRenderer.send('ping')
}
```

### 5.2 使用 eventTrace（Electron 内置）

启动时添加环境变量可开启 IPC 事件追踪：

```bash
ELECTRON_TRACE_EVENTS=1 npm run dev
```

### 5.3 DevTools Network 面板

较新版本的 Electron 支持在 DevTools 的 **Console** 中直接调用 IPC：

```js
// 在 DevTools Console 中测试
window.electron.ipcRenderer.send('ping')
```

## 6. TypeScript 类型检查

在编码阶段即可发现类型错误：

```bash
# 检查主进程 + 预加载脚本的类型
npm run typecheck:node

# 检查渲染进程（Vue 组件）的类型
npm run typecheck:web

# 完整类型检查
npm run typecheck
```

常见类型问题：

| 问题                        | 原因                     | 解决                                                    |
| --------------------------- | ------------------------ | ------------------------------------------------------- |
| `window.electron` 不存在    | 缺少类型声明             | 检查 `src/preload/index.d.ts` 是否正确定义              |
| Vue 组件 props 类型推断失败 | `defineProps` 未使用泛型 | 使用 `defineProps<{ msg: string }>()`                   |
| 模块找不到                  | tsconfig paths 未配置    | 检查 `@renderer` 别名是否匹配 `electron.vite.config.ts` |

## 8. 构建与打包调试

### 8.1 构建检查

```bash
# 完整构建（含类型检查）
npm run build

# 仅构建不检查类型（快速验证）
npx electron-vite build
```

构建输出在 `out/` 目录：

- `out/main/index.js` — 主进程产物
- `out/preload/index.js` — 预加载脚本产物
- `out/renderer/` — 渲染进程静态资源

### 8.2 预览构建产物

```bash
npm run start   # 等同于 electron-vite preview
```

用于验证构建后的应用是否正常运行，排除开发模式特有的问题。

### 8.3 打包调试

```bash
# 解包模式（不生成安装包，方便检查文件结构）
npm run build:unpack

# 分平台打包
npm run build:linux   # 生成 AppImage / snap / deb
npm run build:win     # Windows 安装包
npm run build:mac     # macOS DMG
```

打包产物在 `dist/` 目录。若打包后应用行为异常，可使用解包目录直接运行排查：

```bash
./out/main/index.js   # 不适用，需通过 electron 运行
# 正确方式：
npx electron ./dist/linux-unpacked/
```

## 9. 常见问题排查

### 9.1 启动白屏

- **原因**：渲染进程 Vite 服务未就绪，或 `ELECTRON_RENDERER_URL` 环境变量未设置
- **排查**：
    1. 检查终端中 Vite 是否输出了 Local URL
    2. 在主进程中打印 `process.env['ELECTRON_RENDERER_URL']` 确认值
    3. 尝试在 DevTools Console 中手动 `location.href = 'http://localhost:5173'`

### 9.2 IPC 消息无响应

- **原因**：preload 脚本未正确加载，或 contextBridge 暴露失败
- **排查**：
    1. 在 DevTools Console 中检查 `window.electron` 是否存在
    2. 检查 `BrowserWindow` 的 `webPreferences.preload` 路径是否正确
    3. 确认 `sandbox` 设置（当前项目为 `false`）

### 9.3 Electron 安装失败

- **原因**：国内网络无法从 GitHub Releases 下载 Electron 二进制
- **解决**：
    ```bash
    npm config set electron_mirror https://npmmirror.com/mirrors/electron/
    npm install
    ```

### 9.4 Linux 下缺少系统依赖

Electron 在 Linux 上需要以下系统库：

```bash
sudo apt install -y build-essential libgtk-3-dev libnotify-dev \
  libnss3 libxss1 libasound2t64 libxtst6
```

### 9.5 HMR 不生效

- **原因**：Vite 开发服务器端口冲突或 WebSocket 连接失败
- **排查**：
    1. 检查终端中是否有 Vite 报错
    2. 确认没有其他服务占用 5173 端口
    3. 尝试清除缓存：`rm -rf node_modules/.vite`

## 10. 性能分析

### 10.1 主进程性能

使用 Node.js 内置的性能分析工具：

```bash
# CPU 分析
node --prof ./node_modules/.bin/electron-vite dev

# 生成火焰图
node --prof-process isolate-*.log > profile.txt
```

### 10.2 渲染进程性能

- 使用 DevTools **Performance** 面板录制和分析
- 使用 `console.time()` / `console.timeEnd()` 测量关键操作耗时
- Vue 组件级性能：在 DevTools **Performance** 面板中查看 Layout / Paint 耗时

### 10.3 内存分析

在 DevTools **Memory** 面板中：

- **Heap Snapshot**：快照对比定位内存泄漏
- **Allocation Timeline**：追踪内存分配时间线
